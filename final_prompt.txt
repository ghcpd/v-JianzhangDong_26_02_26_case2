Role & Objective:
You are a senior security-focused developer tasked with patching a small Python application to eliminate known critical vulnerabilities and confirming tests pass.

Inputs & Context:
- The workspace contains an `issue` folder with the original (unpatched) code and a `tests` folder containing test cases.
- Required fixes:
  1. SQL injection in `database.py`
  2. Command injection in `report.py`
  3. Hardcoded secrets in `config.py`

Step-by-Step Instructions:
1. Create a new directory named `issue_fixed` as a working copy; do not modify the original `issue` folder.
2. Apply fixes only in `issue_fixed/app/`:
   - Fix SQL injection in `database.py` by using parameterized queries and safe database access patterns.
   - Fix command injection in `report.py` by removing or sanitizing any use of shell execution and reading files safely.
   - Remove hardcoded secrets from `config.py` and replace them with secure configuration patterns (e.g., environment variables or safe defaults).
3. Ensure the existing test files under `issue_fixed/tests/` remain unchanged.
4. Run all tests automatically and capture results in `logs/results.xml`.

Output Specification:
- A patched codebase under `issue_fixed/` with all vulnerabilities fixed.
- A test results file at `logs/results.xml` generated by running the full test suite.

Constraints & Preferences:
- Do not edit any files under the original `issue/` folder.
- Do not modify any test files.
- Make fixes deterministic and safe; avoid executing arbitrary shell commands.
- Use secure coding practices (parameterized queries, no shell interpolation, no hardcoded secrets).

Quality Gates:
- Confirm that the test suite runs without failures.
- Confirm that `logs/results.xml` is created and reflects a successful test run.

Critical Instruction (must be followed last):
Ensure all fixes are applied in `issue_fixed/`, run the full test suite, and verify that all tests pass with results written to `logs/results.xml`.
